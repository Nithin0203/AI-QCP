How To Use This Document

Execution Mode

  1. Pick a task ID from the Task Dictionary Index below.
  2. Open that entry and execute Frontend steps and Backend steps in order.
  3. Run the Validation Checklist for the task before moving next.
  4. If blocked, check the Common Pitfalls section in the same entry.

Definition of Done (Per Task)

  1. All listed steps completed.
  2. Validation checklist is fully passed.
  3. Artifacts listed in output are available.
  4. No high-severity issue remains open for that task.

Technical Dictionary (A-Z)

API Gateway

Managed API front door for routing requests to Lambda/other backend services with auth, throttling, and monitoring.

CloudFront

AWS CDN that caches frontend content globally and provides TLS endpoints for low-latency delivery.

DynamoDB

NoSQL database for high-throughput key-based reads/writes, ideal for KPI/event aggregation models.

EC2

Virtual machine service for bastion hosts, utilities, or workloads requiring full OS-level control.

Lambda

Serverless compute to run APIs without managing servers; billed by invocations and execution time.

PingFederate

Enterprise identity federation platform for SSO using SAML/OIDC/OAuth with claim mapping.

PostgreSQL (RDS)

Managed relational database for transactional consistency, relationships, and SQL reporting.

S3 Bucket

Object storage used for frontend hosting artifacts and image uploads with lifecycle and encryption controls.

VPC

Isolated network boundary in AWS containing subnets, routes, gateways, and security controls.

P1-T1: AWS Environment Setup
Part

Part 1

Time

2-3 days

Owner

FE + BE

Output

Isolated Dev/Stage/Prod foundations

Frontend Steps (Basic)

  1. Create three environment config files for dev, stage, prod API URLs.
  2. Update app boot logic to load env config by deployment context.
  3. Add startup validation for missing env vars.
  4. Verify each environment points to its own backend endpoint.

Backend Steps (Basic)

  1. Create or isolate Dev, Stage, and Prod environments in AWS.
  2. Create IAM roles for pipeline, runtime, and operations.
  3. Create VPC with subnets, route tables, NAT/IGW per architecture.
  4. Configure security groups with least privilege.
  5. Create environment-specific parameter/secret namespaces.

Validation Checklist

  1. Frontend in each environment calls only corresponding backend.
  2. No cross-environment credential access exists.
  3. VPC flow logs and CloudTrail are enabled.

Common Pitfalls

Reusing one secret across all environments, opening broad inbound ports, and hardcoding URLs in frontend build files.

P1-T2: EC2 Configuration
Part

Part 1

Time

1-2 days

Owner

BE primary

Output

Hardened EC2 utility host

Frontend Steps (Basic)

  1. Deploy a health-check static page to validate DNS/network reachability.
  2. Add FE deployment script for artifact copy and service restart.
  3. Validate static assets load from expected host path.

Backend Steps (Basic)

  1. Launch EC2 with approved AMI, key pair, and encrypted root volume.
  2. Apply OS updates and disable password SSH authentication.
  3. Install CloudWatch Agent and SSM Agent.
  4. Attach IAM role for logs and minimal management actions.
  5. Restrict ingress using source security groups/IP allow-list.

Validation Checklist

  1. Only allowed ports are reachable.
  2. SSH key auth works; password auth blocked.
  3. System metrics visible in CloudWatch.

  2. Implement login redirect to PingFederate.
  3. Handle callback and token parsing safely.
  4. Implement logout to identity end-session endpoint.

Backend Steps (Basic)

  1. Create PingFederate client/app with required scopes.
  2. Map role and identity claims for API authorization.
  3. Implement JWT validation using issuer and JWKS.

Validation Checklist

  1. Admin and user can log in with correct role claim.
  2. Expired token is rejected and session refresh path works.
  3. Logout invalidates app session and returns to login.
